# 如何安全提供登入資訊給協助者（建議）

請以「安全、最小權限、可撤銷、短期」為原則提供登入資訊。以下為具體步驟與建議：

1. 絕對不要在聊天或公開平台貼出完整密碼或長期私密金鑰。
2. 優先使用臨時憑證：建立短期 API token、一次性密碼或臨時使用者，完成後立即撤銷。註明到期時間與用途。
3. 使用秘密管理工具：將密碼放在 Secrets Manager / Vault（如 AWS Secrets Manager、Azure Key Vault、HashiCorp Vault），並分享「取用路徑或一次性存取連結」，而非直接值。
4. 最小權限原則：只授予完成任務所需的最小權限，避免提供管理員或廣泛讀寫權限。
5. 如果必須傳送檔案，請加密檔案（例如 ZIP + 強密碼）並透過不同通道傳送密碼（附件與密碼分開傳遞）。
6. 可用替代方式：在本機執行需驗證的指令並截圖（遮蔽敏感欄位），或匯出不含密碼的日誌/設定範本。
7. 提供使用說明而非原始密碼：若目的是讓人幫忙設定，提供設定步驟、環境變數名稱範例、以及如何在本機載入憑證的指令，範例如下。

範例：建立短期 token（示意，不貼真實值）
```
# 建立臨時 token（示意）
# 由系統管理員在安全環境執行，然後把 token 設為環境變數或寫入秘密管理器
export MY_APP_TOKEN="<TEMP_TOKEN_GOES_HERE>"
# 在完成工作後撤銷或刪除該 token
```

範例：透過秘密管理器分享（示意）
```
# 在 Vault 中建立秘密，並給予協作者「讀取」權限的短期策略
vault kv put secret/projectX/service-creds username="service-user" token="<TEMP_TOKEN>"
# 分享取用路徑（例如：secret/data/projectX/service-creds），而非直接貼 token
```

我能提供的協助：
- 撰寫設定範本、環境變數指令、或範例程式碼以從秘密管理器取得憑證。
- 指導如何建立臨時憑證、設定最小權限政策、以及撤銷流程。

不可行與注意事項：
- 請勿在聊天中傳送真實密碼或長期金鑰；若必須提供，請遵循上面步驟並先建立短期憑證。
- 提供憑證前，確認有明確到期與撤銷流程，並記錄誰在何時使用。
